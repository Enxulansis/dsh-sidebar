# 故障排查与反馈

先确认当前窗口实际加载的扩展版本、后端版本及home，再定位问题。运行 **DeepSeek Harness: 显示运行时输出** 可查看后端输出；必要时开启 `deepseekHarness.ui.diagnostics`，复现后关闭，避免持续记录大量细节。

| 现象 | 检查与处理 |
| --- | --- |
| 找不到侧栏 | 运行“打开聊天”命令；检查扩展是否在当前窗口启用、工作区是否受信任 |
| 安装后看不到新功能 | 执行“Developer: Reload Window”；区分日常窗口与独立用户数据窗口 |
| 后端无法启动 | 检查Node版本、executable路径、启动参数及文件权限；查看输出中的实际错误，不反复安装扩展 |
| 只能看到普通／计划 | 两者是模式。确认后端为RC4、权限目录加载成功，未使用改变目录的自定义profile |
| 模型列表存在但发送失败 | 检查当前后端凭据、接口地址、模型ID、网络和额度；模型列出不代表调用一定成功 |
| Router预设未显示 | VSIX不自带已安装的Router环境；检查实际profile。基础安装可用standard，不必为此导入旧插件 |
| 原会话消失 | 检查home是否切换。不同数据目录不会自动合并；先保留旧目录，避免覆盖 |
| 图片取消没有恢复草稿 | 核对配套修补报告、是否重启后端，以及停止发生在准备阶段还是已受理之后 |
| 断线点击审批后没有执行 | 等连接恢复，阅读恢复的卡片并重新决定；离线决定不会自动重放 |
| 停止后还有消息或任务 | 当前生成、队列和后台任务分别检查；停止不代表全部清空 |
| 跨工作区搜索没有结果 | 检查后端索引与profile；不要据此判断当前工作区搜索失效或数据被删除 |
| 修补报未知哈希 | 停止；记录目标版本、依赖锁文件和错误。不改断言，不强行覆盖未知文件 |
| 自定义插件报错 | 第三方插件不在本项目维护范围；在不含该插件的独立环境确认侧栏问题，插件兼容问题交其维护者 |

## 重连与重启

**DeepSeek Harness: 重连 / 重启运行时** 依据后端连接方式执行恢复，可能重启受管理后端，因此不要把它当作无影响的刷新按钮。先确认是否有正在运行的工具或后台任务。排障不需要断开整台电脑的网络。

## 提交反馈

在 [GitHub Issues](https://github.com/Enxulansis/dsh-sidebar/issues) 提交问题。请准备以下信息：

- Windows、VS Code、Node、侧栏和后端版本。
- 最短复现步骤，预期和实际表现，是否涉及特定会话或自定义profile。
- 是否在独立home复现，是否装有第三方插件；仅填写名称和版本即可。
- 脱敏错误片段与必要截图，移除密钥、带令牌的本机连接地址、私人文件内容和个人路径。

不要上传整个home、设置备份或会话数据库。诊断日志可能含提示词、工具参数及路径；先检查内容再分享。
